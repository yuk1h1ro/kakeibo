# 家計簿 (kakeibo)

自分専用のシンプルな家計簿 PWA です。カテゴリ別の支出記録、月次レポート、そして彼女から預かったお金の残高管理ができます。スマホのホーム画面に追加すれば、ネイティブアプリのように使えます。

- ログインは **Google アカウントのみ**(メールアドレス+パスワードでのログインは使いません)
- データは [Supabase](https://supabase.com/)(無料枠)に保存されます
- ホスティングは GitHub Pages(無料)で、main ブランチへの push で自動デプロイされます
- Row Level Security (RLS) により、ログインした本人以外はデータに一切アクセスできません

## 機能

| タブ | 説明 |
| --- | --- |
| 入力 | **カテゴリを選ぶ → 金額を打つ**の2タップで記録できます(カテゴリを押すと金額欄に自動でフォーカスし、金額は打つそばから `1,234` と桁区切りされます)。日付・お店・メモ・彼女の負担分は「詳細」に畳んであり、必要なときだけ開きます。続けて何件も入れるときは **「保存して続ける」** を押すと、日付とカテゴリを残したまま次の1件に進めます。支出には **気分(満足 / 普通 / 後悔)** を1タップで付けられます(任意)。スマホでは金額を大きな自前のテンキー(＋ − × ＝つき)で打てます。金額欄には **％キーと「税込 +10% / +8%」ボタン** があり、レシートの税抜き価格を打ってから1タップで税込にできます(下記)。カメラでレシートを撮影すると、店名・合計金額・日付をAI(Gemini)が読み取って自動入力することもできます(要・無料APIキー設定。最大5枚まで続けて撮影できます)。同じお店で前に選んだカテゴリは自動で入り、よく使う入力はテンプレートから1タップで呼び出せます。食事などを支払ったとき、そのうち「彼女の負担分」を入力すると、預かり金残高から自動で差し引かれます。**割引券で安くなった回や、誰かにご馳走になった回**も「詳細」から記録できます(支出の金額は増えません。下記)。 |
| 履歴 | 記録した取引の一覧を確認・編集・削除できます。カレンダーの日付を**タップするとその日の明細**が下に出て、その明細カードの **「＋ ◯月◯日で入力する」** を押すと、その日付を入れた状態で入力を始められます。上部の検索欄で**店名・メモ・カテゴリ名を横断して検索**でき、並べ替え(日付順・金額順)・期間・カテゴリで絞り込んだ条件は名前を付けて保存できます。明細は**左に払うと削除・右に払うと編集**、**長押しでその場のメニュー**(複製・編集・削除)、**「選択」からまとめてカテゴリ変更・まとめて削除**ができます。削除は確認ダイアログではなく、**消したあと数秒出る「元に戻す」**で取り消します。**引き下げると更新**され、最後に取り込んだ時刻(「10:32 に更新」)が出ます。見出しの年月を押すと**年月ピッカー**で一気に遡れます。 |
| レポート | 月ごとの支出合計とカテゴリ別の内訳を確認できます。自分の実質支出(彼女の負担分を除いた額)で集計されます。**支出ペースの参照線・月末着地の予測・日別ヒートマップ・固定費の合計・繰り返しの登録候補・年のまとめ・日/週/月/年の粒度切替・おごり/値引きの振り返り**もここにあります(下記)。 |
| 彼女 | 預かり金の残高と入出金の履歴を確認できます。彼女に見せる**閲覧専用の共有リンク**(下記)を発行・無効化でき、明細ごとのコメントのやりとりもここで行います。Discord 通知の設定と、**これまでの履歴をまとめて Discord に送る**導線(下記)もこのタブにあります。 |
| 資産 | 銀行・証券・現金などの残高と、ローンなどの負債を記録して**純資産の推移**を見られます(自動連携はせず、月1回くらい手で残高を書き写す使い方を想定しています)。`supabase/migration-assets.sql` を実行するまではタブごと表示されません(下記)。 |

### 金額の計算(電卓・％・税込)

金額欄のすぐ下に、2段の計算ボタンがあります。**扱うのは円単位の整数だけ**で、小数点キーはありません(保存される金額も常に整数です)。

- **1段目 `＋ − × ＝`** — 金額欄に打った数どうしをその場で計算します。`＝` を押し忘れて保存しても、保留中の計算は自動で確定されます。
- **2段目 `％` `税込 +10%` `税込 +8%`**

**`％` は電卓と同じ挙動です。** 直前の値に対する割合として働きます。

| 押した順 | 結果 | 意味 |
| --- | --- | --- |
| `1000` `＋` `10` `％` | `1100` | 1000 の 10% を足す |
| `1000` `−` `10` `％` | `900` | 1000 の 10% を引く |
| `1000` `×` `10` `％` | `100` | 1000 の 10% |

演算子(`＋ − ×`)を押していないときは **`％` は何も起きません**(ボタンも押せない見た目になります)。「1000 の何に対する 10% なのか」が決まっていないためです。よくある電卓のように「打った数を 1/100 にする」動きにはしていません — この家計簿は円未満を持たないので、`1000` が黙って `10` という別の金額に変わってしまい、打ち間違いと見分けが付かなくなるからです。

**`税込 +10%` / `税込 +8%` は1タップで税込にします。** 日本の消費税は標準10%と軽減8%(持ち帰りの飲食料品など)の2本立てなので、両方を並べています。`1000` と打って `税込 +10%` を押せば `1,100`、`税込 +8%` なら `1,080` です。計算の途中(`980 ＋ 200` など)で押した場合は、先に計算を確定してから税込にします。

- **端数(円未満)は切り捨て** です。`333` の10%は `366`(366.3 の切り捨て)。レジの端数処理として最も一般的なやり方に揃えています。切り上げ・四捨五入を選ぶ設定は **あえて用意していません** — 選べるようにすると使うたびに「今どの設定だったか」を思い出す必要が生まれるのに対し、ずれるのはたかだか1円で、それは金額欄を打ち直せば済むからです。
- **押した結果は文字でも出ます。** 「`1,000 → 税込 1,100(10%)`」のように押す前の額を並べて表示します(端数を落としたときは「円未満切り捨て」も添えます)。黙って数字だけが変わると、打ち間違いと区別が付かないためです。この行は金額を打ち直すと消えます。

**使える金額欄**: 支払い金額(`％` と税込の両方)、彼女の負担分・彼女が払った額(税込のみ。この2つには電卓が無いので `％` は出ません)。
**使えない金額欄とその理由**: 分割の内訳は「内訳の合計 = 支払い総額」が揃わないと保存できないため、1行だけ税込にすると保存できなくなります(総額を税込にしてから分けるのが正しい順番です)。資産の残高は価格ではなく口座の残高なので、消費税を掛ける対象がありません。

### おごってもらった回・割引で安くなった回

「割引券で無料になった」「先輩にご馳走になった」ように、**実際に払った額が本来の値段より安かった**回があります。入力の「詳細」を開くと、**おごってもらった / 割引・ポイント** の2つから選んで記録できます。

**記録すべきか。答えは「する」です。** とくに**おごってもらったものは必ず記録する価値があります**。誰に・いつ・いくらぶんご馳走になったのかは、あとから思い出そうとしても出てきません。お礼を言うにも、お返しをするにも、まず残っていないと始まらないからです。「払っていないから家計簿には要らない」は、家計の数字としては正しくても、**相手への向き合い方としては間違っている**と考えました。

そのうえで、**支出の金額は1円も動かしません。**

| 記録すること | どこに入るか |
| --- | --- |
| 実際に自分が払った額 | `金額`。支出の合計・カテゴリ別・支出ペース・予算に入る**唯一の数字** |
| おごり・値引きで浮いた額 | 別の欄。合計にもグラフにも**入らない**(払っていないお金なので) |
| おごってくれた人 | 別の欄。履歴の行とレポートに名前が出る |

- **全額おごってもらった回(支払い 0円)も保存できます。** 金額欄は空のままで構いません(おごり・値引きを入れたときだけ 0円 が通ります。理由の無い 0円 はこれまでどおり保存できません)。履歴には `¥0` と出て、その横に「田中さんのおごり ¥3,200」と添えられます。
- **本来の値段は「払った額 + 浮いた額」** です。入力中にも「本来 ¥3,200 のところ、全額 田中さんのおごり です。支出は ¥0 で記録されます」と、保存前に文章で出ます。
- **おごってくれた人の名前は、過去の記録から1タップで選べます**(最近ご馳走になった順)。毎回打ち直すと「田中 / 田中さん」と揺れて、同じ人が別人に割れてしまうためです。
- **彼女が払った回(「支払った人」)とは別物です。** あちらは**あとで精算するお金**で預かり残高が動きます。おごりは**返さなくていい好意**なので、残高は1円も動きません。
- **分割(カテゴリを分けて記録)とは同時に使えません。** 浮いた額を内訳のどれに割り当てるかを決められないためです(分割を開くとその場で「外れます」と出ます)。
- 記録は**自分用**です。彼女に見せる共有ページには出ません(第三者にご馳走になった記録は、彼女の残高と関係がないためです)。
- この機能を使うには [`supabase/migration-favor.sql`](supabase/migration-favor.sql) の実行が必要です(下記)。実行するまでは導線が表示されないだけで、記録・入力・同期はこれまでどおり動きます。

### レポートの見方

月ごとの合計・カテゴリ別・お店別・ランキング・曜日別/時間帯別・気分の振り返りに加えて、次のカードがあります。

- **支出ペース** — その月の累積支出の折れ線に、「今日時点でここまでなら適正」という参照線(破線)を重ねます。基準は **設定した予算**、予算が未設定なら **直近3ヶ月のうち記録のある月の平均** です(どちらの基準を使ったかはカードに明記されます)。予算はカード内の「予算を設定する」から決められます(この端末にだけ保存されます)。過去に記録がなく予算も未設定のときは、根拠が無いので線を引きません。
- **月末の着地(予測)** — いまのペースが続いた場合の見込みを、**幅つき**で出します。「予測」と明示し、何日分の実績から計算したかも添えます。**月初(経過7日未満)・支出のあった日が3日未満・過去の月・月末当日は出しません**(サンプルが足りないまま断定的な数字を出さないため)。
- **日別ヒートマップ** — その月の使った額を、色の濃さ(1色の濃淡)と金額の両方で示します。日をタップすると正確な金額と件数が出ます。
- **毎月の固定費** — 繰り返し入力に登録済みのものだけを月額・年額に換算して合計します(毎週は 365÷7、毎年は ÷12)。登録していない定額サービスは含まれません。
- **繰り返しの登録候補** — 過去の記録から、同じお店・ほぼ同じ金額・ほぼ一定の間隔で続いている支払いを探して提案します。**提案するだけで、登録はボタンと確認を経たときだけ**行われます。登録しても過去の分が自動生成されることはありません(開始日は翌日になります)。すでに登録済み(停止中を含む)のお店と、「今は不要」を押した候補は二度と出ません。
- **粒度を変えて見る** — 同じ棒グラフを 日/週/月/年 で切り替えられます(直近14日 / 8週 / 12ヶ月 / 5年)。月表示・期間表示の選択はそのまま残ります。
- **年のまとめ** — 見ている月の年について、合計・月別推移・カテゴリ上位・お店上位・気分の内訳をまとめて見られます(進行中の年は「途中集計」と表示します)。
- **おごり・値引き** — その期間に **誰に何回・いくらぶんご馳走になったか** を人ごとに出します(最後にご馳走になった日つき)。割引・ポイントで浮いた額もここにまとめます。ここに出る金額は**払っていないお金**なので、支出の合計には入っていません。1件も記録が無い期間ではカードごと出ません。
- **タグ別の支出** — タグ(旅行・デートなど)を軸にした内訳です。タグを押すと、**その中で一緒に付いているタグ**(「2026和歌山」などの行き先)と、**回ごと**の集計が出ます(下記「[旅行を1回ずつ見る](#旅行を1回ずつ見る2段階の絞り込み)」)。

### 設定(歯車ボタン)

画面右上の歯車ボタン(⚙️)から、次の設定を開けます。

- **カテゴリ設定** — 支出カテゴリのカスタマイズ(下記)
- **繰り返し入力** — 家賃・サブスクなどの自動記録(下記)
- **CSV で書き出す** — 記録の控えを端末に保存する(バックアップ。下記)
- **金額のテンキー** — 自前のテンキーを使うかどうか(既定の「自動」ではスマホ・タブレットのときだけ使います)
- **画面の金額を伏字にする** — 人前で開くときの目隠し(下記)
- **アプリ切替時に画面を隠す** — ほかのアプリに切り替えている間だけ画面を覆います(下記)
- **テンプレート** — 保存したテンプレートの確認と削除
- **同期できなかった記録** — サーバーに断られた記録の確認・再送・破棄(残っているときだけ出ます。下記)
- **Supabase の接続設定** — いまの接続先の確認と、接続設定のやり直し

#### CSV で書き出す(バックアップ)

設定の **「CSV で書き出す」** から、記録を CSV ファイルとして端末に保存できます。**これはバックアップのための機能です。** Supabase の無料プランには自動バックアップがなく、操作ミスや事故で消えたデータは戻せません。1年分溜まってから失うと痛みが大きいので、**月に一度、全期間で書き出しておく**ことをおすすめします(ファイル名に書き出した日が入るので、前の控えを上書きしません)。

- **期間を選べます** — 全期間 / 年ごと / 月ごと。バックアップとして取るなら**全期間**です
- **1件も欠けません** — まだサーバーに送れていない記録(オフライン中に付けた分)も、書き出しに含めます
- **表計算でそのまま開けます** — Excel でも文字化けしないよう、BOM 付きの UTF-8 で書き出します。金額は `¥` も桁区切りも付けない数値なので、合計や並べ替えがそのままできます
- **メモや店名にカンマ・改行・引用符が入っていても壊れません**(RFC 4180 のとおりに囲みます)。「ラーメン,餃子」というメモで列がずれることはありません
- **画面の金額を伏字にしていても、書き出す中身は伏せません。** 伏字の控えには意味がないためです。中身が見られて困る場所には置かないでください
- 記録が0件の期間は書き出せません(空のファイルを作っても「バックアップを取った」という記憶だけが残るため)

書き出す列は次の18列です。カテゴリは ID ではなく**表示名**で出します(あとで開いた自分が読めるように)。カテゴリ名は変えられるので、元の ID も末尾に残します。

`日付` / `種別`(支出・預かり・返金・調整) / `金額` / `カテゴリ` / `お店` / `メモ` / `タグ`(空白区切り) / `彼女の負担分` / `彼女が払った額` / `気分`(満足・普通・後悔) / `おごり・値引き額` / `おごり・値引きの別`(おごり・割引) / `おごってくれた人` / `記録元`(手入力・繰り返し入力) / `記録日時` / `分割ID`(分割した会計の束ね) / `カテゴリID` / `ID`

**保存のされ方は開き方によって変わります。**

- **Safari のタブで開いているとき** — 押すとダウンロードされ、「ファイル」アプリのダウンロードに入ります
- **ホーム画面に追加した PWA として開いているとき** — **共有シート**が開きます。「"ファイル"に保存」で端末に残せますし、そのまま自分宛のメッセージや iCloud にも送れます(端末ごと壊れたときのことを考えると、むしろ端末の外に出しておくほうが安心です)。PWA では iOS のバージョンによってダウンロードが黙って効かないことがあるため、こちらを先に使います
- どちらも使えないブラウザでは、新しいタブに中身を表示します(全部を選んでコピーし、テキストとして保存してください)

**読み込み(インポート)はありません。** この CSV からアプリへ書き戻す手段は用意していないので、**復元は中身を見ながら手で入力し直す**ことになります。それでも「記録がどこにも残っていない」より遥かにましです。CSV は Excel や Google スプレッドシートでそのまま開けるので、集計や確認だけならファイルのままでもできます。

#### 同期できなかった記録

サーバーに送れなかった記録は、**捨てずにこの端末へ取り置きます**。以前は「送り直しても通らない」と判断した書き込みを黙って捨てていたため、分割した会計の途中の1件が弾かれると、3,000円の会計が2,000円になり、しかも画面には何の痕跡も残りませんでした。

- 取り置いた記録は、設定の **「同期できなかった記録」** から中身を確かめられます(残っているときだけ、この行が出ます)
- 原因が直ったら **「もう一度送る」**、要らない記録なら **「破棄する」**(確認あり)。**破棄を押すまで、端末から消えることはありません**(件数の上限もありません)
- 分割した会計は、1件でも送れなければ**会計ごと**取り置きます(半分だけ保存された会計を残さないため)
- 同じ記録が何度も断られたときも取り置いて先へ進みます(1件の異常が、後ろの記録すべてを永久に止めてしまわないようにするため)

#### 画面の金額を伏字にする(人前で開くとき)

画面右上の**目のボタン**を押すと、画面に出ている金額がすべて `¥•••••` になります。もう一度押すと戻ります。

- **金額によらず同じ伏字**なので、桁数(だいたいの金額)も分かりません
- 明細・合計・預かり残高・レポートの数字・**グラフの軸・カレンダーの日別合計・ヒートマップ**まで伏せます
- 伏せている間、金額の文字は画面のデータそのものから消えています(文字を選んでコピーしても出てきません)
- **伏せないもの**: 入力中の金額欄・レポートの予算の入力欄(打っている本人が読めないと困るため)と、**グラフの棒の高さ・ヒートマップの濃さ**(形は残るので、「どの日に多く使ったか」の傾向は見えます)
- 既定は「表示」です。押した状態はこの端末に保存され、再読み込みしても伏字のままです
- Discord への通知や変更履歴に残る文字列は、伏字になりません(記録としての正しさを優先しています)

> **「アプリ切替時に画面を隠す」との違い**
> こちらは**自分で押す**もので、画面を開いたまま金額だけを隠します。
> 「アプリ切替時に画面を隠す」は**自動**で、アプリを離れている間だけ画面全体を覆います(見ている最中は何も変わりません)。

#### アプリ切替時に画面を隠す

ほかのアプリに切り替えたり、タブ一覧を開いたりしている間、画面全体を覆って金額を隠します(既定でオン)。ふとした瞬間ののぞき見を減らすためのもので、スクリーンショットや画面収録は防げません。

#### カテゴリ設定

支出カテゴリを自由にカスタマイズできます。

- **追加** — 絵文字と名前を入力して新しいカテゴリを作成
- **名前・絵文字の変更** — 各カテゴリの「編集」からその場で変更
- **並べ替え** — ↑↓ボタンで入力画面での表示順を変更
- **隠す** — 選択肢から消します。**削除ではありません**。過去の記録は今までどおりそのカテゴリ名で表示され、シート下部の「隠しているカテゴリ」からいつでも **「戻す」** で選択肢に戻せます(元の並び順のまま戻ります)

カテゴリは Supabase に保存されるため、複数の端末で同じ設定が同期されます。初回起動時には既定の8カテゴリ(食費・外食・日用品など)が自動で登録されます。なお、カテゴリの編集はオンライン時のみ可能です。

#### 繰り返し入力(家賃・サブスクの自動記録)

家賃やサブスクのように毎回同じ支出は、**「毎月N日」「毎週X曜」「毎年M月N日」** で登録しておくと自動で記録されます。

- その日が来たあと、**アプリを開いた時点で**まとめて記録されます(しばらく開いていなかった期間の分も、開いた瞬間にすべて遡って作られます)
- 同じ日の記録が二重に作られることはありません
- **作りかけで失われた分は、次にアプリを開いたときに自動で作り直します。** 記録として残せたことを確かめるまで「生成済み」とは見なさないためです。**自分で削除した記録が作り直されることはありません**(消した時点で作り直しの対象から外れます)
- 自動生成された記録は履歴で「自動生成」と表示され、手入力の記録と同じように編集・削除できます
- 一時的に止めたいときは「停止」、やめるときは「削除」を押します(すでに生成された記録は残ります)

> 「毎月31日」のようにその月に無い日を指定した場合は、その月の末日(2月なら28日)に記録されます。

#### タグ(1件に複数)

カテゴリとは別の軸で、1件に最大5つまでタグを付けられます(「旅行2026」「デート」など)。入力・編集の **「詳細」** の中にあり、空白で区切って打つか、過去に使ったタグを1タップで選べます(`#` は付けても付けなくても同じです)。

履歴では **タグのチップで絞り込む**ほか、検索欄に `#デート` や `デート` と打っても引けます。絞り込んだ条件はこれまでどおり名前を付けて保存できます。

> タグは**メモとは別に保存**しています(メモを書き直してもタグは消えません。メモの中身は共有ページには出ませんが、タグもあなた専用の整理軸で、彼女には表示されません)。

#### 旅行を1回ずつ見る(2段階の絞り込み)

「旅行でいくら使ったか」だけでなく、**「今回の和歌山旅行でいくら使ったか」**を見られます。やることは、その旅行の記録に **`旅行` と `2026和歌山` の2つを付けるだけ**です。

レポートの **「タグ別の支出」** で `#旅行` を押すと、**その記録に一緒に付いているタグ**が中に出ます。`#2026和歌山` を押せば、その旅行だけのカテゴリ内訳と回ごとの集計になります。`#デート × #2026誕生日`、`#出張 × #大阪` にもそのまま効きます。

- **行き先タグは、上のタグ一覧には出しません。** タグ別集計は1件に2つ付いていれば**どちらにも満額で**数えるので(按分すると「旅行でいくら使ったか」が答えられなくなります)、`旅行` と `2026和歌山` を並べると同じ金額が必ず2度出ます。**いつも別のタグと一緒にしか出てこないタグ**を内側に畳んで、二重計上が増えないようにしています(隠していることと理由は画面にも書いてあります)
- **どれが「内側」かは、自分で登録しません。** 「そのタグが付いた記録が1件残らず、より広いタグと一緒に付いているか」だけで決まります。広さは **レポートの「特別な支出」に選んでいるタグ(旅行・デート・出張…)が親** → それ以外は**件数が多い方が親**、の順です。**1度でも単独で出てくれば内側にしません**(どこからも辿れないタグができて、その金額が一覧から消えるのを防ぐため)
- **掘れるのは1段だけ**です(`旅行 → 2026和歌山` で止まります)
- **これまでの「回ごと」はそのまま残しています。** 記録が7日より長く空いたところで別の回として切る集計で、**行き先タグを付けていない過去の旅行は、こちらでしか個別に見られません**

> **階層タグ(タグの親子関係)は作っていません。** 理由は3つです。
>
> 1. **入力が増えます。** 入力は「カテゴリ → 金額」の最短5タップまで詰めてあり、記録のたびに「親を選ぶ → 子を選ぶ」を挟みたくありません。いまの形なら、旅行モードを始めるときに行き先を1度打つだけです
> 2. **データの形が変わります。** タグは `transactions.tags`(文字列の配列)で、親子を持たせるには別テーブルか命名規則が要ります。すると**タグを読むところすべて**(履歴の絞り込み・検索・CSV・共有・レポート)に階層の概念が漏れます
> 3. **2階層で止まる保証がありません。** 次は「1日目」「往路」が欲しくなります
>
> 保存されるのは `['旅行', '2026和歌山']` という、これまでとまったく同じ文字列の配列です。**マイグレーションは要りません。**

#### 過去の旅行に、あとから行き先タグをまとめて付ける

行き先タグが自動で付くのは旅行モードを使ったときだけなので、**すでに終わった旅行には何も付いていません**。先週の旅行35件を1件ずつ開いて打つのは続かないので、レポートの **「回ごと」の行から1タップ**でまとめて付けられます。

1. レポートの「タグ別の支出」で `#旅行` を押す
2. 「回ごと」に出てくる **`8月6日 〜 8月8日`** の行の **「この回にタグを付ける」** を押す
3. 行き先の名前を打つ(過去に使った行き先は1タップで選べます)
4. **「35件に #2026和歌山 を付けます」と件数が出るので、確認してから**「付ける」を押します

- **すでに同じタグが付いている記録は飛ばします**(二重には付きません)
- タグは1件5個までなので、**すでに5個ある記録には付けられません**。そのときは「◯件は付けられませんでした(タグの上限)」と必ず出ます(黙って飛ばしません)
- **付け間違えたら、同じ場所から外せます。** 「この回のタグを外す」に、その回に付いているタグが件数つきで並びます
- 書き込みは1件ずつ順番に積まれ、**通信できないときは復帰後に送られます**。変更は「変更履歴」にも残ります

#### 旅行モード(旅行・デート・出張のあいだ、自動でタグを付ける)

旅行やデート、出張のように**日常とは違う場面の支出**は、レポートで「普段の支出 / 特別な支出」に分けて見られます。ただし1件ずつ手でタグを打つのは続かないので、**「いま旅行中」を1回押すだけで、それ以降の記録に自動でタグが付く**モードを用意しています。

- **始める** — 入力タブのいちばん上にある **「旅行・デート中にする」** を押し、タグを選びます(既定の候補は **旅行・デート・出張**。それ以外も自由に打てます)。**2タップで始まります**
- **行き先の名前(任意)** — 始めるときに **「2026和歌山」** のような行き先を入れておくと、以降の記録に **`旅行` と `2026和歌山` の2つが自動で付きます**(打つのは始めるときの1回だけです)。レポートで[旅行を1回ずつ](#旅行を1回ずつ見る2段階の絞り込み)見るための行き先タグがこれです。**空のままなら、これまでどおり1つだけ付きます**(タップ数は増えません)。過去に使った行き先は1タップで選べます
- **オンのあいだ** — 同じ場所が色付きの帯になり、**付くタグと「何日目か」がずっと出ます**(行き先を入れていれば「#旅行 #2026和歌山 ・ 2日目」と2つとも出ます)。入力フォームの保存ボタンのすぐ上にも「この記録に #旅行 #2026和歌山 が自動で付きます」と出るので、保存する直前に必ず目に入ります
- **終わる** — 帯の **「終わる」** を押します。確認は挟みません(押しにくいと切り忘れるため)
- **この1件だけ外す** — 旅行中でもコンビニで自分用のものを買うことはあります。保存ボタンの上の **「この1件だけ外す」** で、その1件にだけタグを付けずに保存できます(行き先タグごと外れます)。**外した判断は次の記録には持ち越しません**(押し直せば「やっぱり付ける」で戻せます)
- **手で付けたタグとは共存します**(自動のタグと手で選んだタグの両方が付きます)

> **自動では終わりません。** 途中で勝手に切れると、1回の旅行の中で「タグが付いた記録」と「付いていない記録」が混ざり、あとから見分けられなくなるためです。代わりに **8日目からは帯の色が変わり「もう終わっていませんか?」と出ます**(それでも解除するかどうかを決めるのはあなたです)。

> モードの状態は **この端末にだけ**保存されます(記録そのものではなく「いま入力している文脈」のため)。旅行に持って行くスマホと、帰ってから開く PC で別々でいられるほうが、切り忘れの被害が広がりません。
>
> モードが変えるのは **これから記録する分だけ**です。すでに保存された記録には触れません(付け忘れた分は、履歴からその記録を開いてタグを足してください)。

タグを使う機能なので、`supabase/migration-tags-splits.sql` を実行していない環境では**導線ごと表示されません**。

#### 1件を複数カテゴリに分ける

スーパーの1会計を「食費」と「日用品」に分けたいときは、入力タブの **「詳細」→「カテゴリを分けて記録する」** を押します。

- 内訳ごとに **カテゴリ・金額・彼女の負担分** を入れます(内訳は2〜6件)
- **内訳の合計が支払い金額とぴったり一致しないと保存できません**(ここがずれると支出の合計と預かり残高が静かに狂うため)
- 保存すると **内訳ごとに1件ずつの記録**になります。レポートのカテゴリ別も、預かり残高も、分ける前とまったく同じ金額で積み上がります
- 履歴で開くと「分割した記録のうちの1件です」と出ます(その1件だけを直せます)

> 彼女の負担分は**内訳ごと**に持ちます。全体に1つだけ持たせると「どのカテゴリのいくらを彼女が負担したのか」が決まらず、按分の丸めで残高がずれるためです。

#### テンプレート

よく使う支出は、履歴でその記録を開いて **「これをテンプレートにする」** を押すと保存できます。以降は入力タブのテンプレート欄から1タップで、お店・カテゴリ・金額・彼女の負担分がまとめて入ります。

#### お店からのカテゴリの自動選択

支出を保存すると、**お店とカテゴリの組み合わせを覚えます**。次に同じお店を打ち始めると候補が出て、選ぶとカテゴリまで自動で入ります(レシート読み取りでお店が入ったときも同じです)。

自動で入ったカテゴリは、いつでもタップして選び直せます。選び直した内容が新しい記憶になり、そのお店の過去の記録が別のカテゴリで残っている場合は、保存の直後に **「過去の『セブンイレブン』3件も食費に変えますか?」** と確認します(該当が無いときは聞きません)。

#### 感情スタンプ(満足 / 普通 / 後悔)

支出に「その買い物をどう感じたか」を1タップで付けられます(任意。付けなくても構いません)。

- **入力するとき** — 入力タブの「この支出の気分」で押します。もう一度押すと未設定に戻ります
- **あとでまとめて** — レポートタブの「気分の振り返り」から **「まだ気分が付いていない◯件を仕分ける」** を押すと、1件ずつカードで出てきます。**右へ払うと「満足」・左へ払うと「後悔」**、ボタンでも付けられます
- **振り返り** — レポートに「今月の後悔支出 ◯件・◯円」と、後悔が多い曜日が出ます

> 気分の振り返りで見ているのは**曜日だけ**です(「後悔が多い時間帯」は出していません)。支出した時刻そのものはどこにも記録していないためです。
> なお、レポートの「時間帯別の支出」はこれとは別のカードで、そちらは**アプリに記録した時刻**(`created_at`)をもとにした目安です(支出した時刻ではないことを画面にも注記しています)。

この機能を使うには `supabase/migration-satisfaction.sql` の実行が必要です(下記)。実行するまでは、気分の導線が表示されないだけで、記録・入力・同期はこれまでどおり動きます。

### 預かり金の仕組み

1. 彼女から先にまとまったお金(例: 3 万円)を預かり、「預かり金」として記録します
2. 食事などを支払ったとき、支出の入力時に「彼女の負担分」(例: 1,500 円)を入力します
3. 負担分が預かり金残高から自動で差し引かれ、現在の残高がいつでも確認できます

#### 残高の符号 — 「預かり中」と「立て替え中」

残高は**マイナスにもなります**。数字の符号だけでは意味が読めないので、金額は常に絶対値で出し、意味は言葉で示します。

| 残高 | 表示 | 意味 |
| --- | --- | --- |
| プラス | **預かり中** | 彼女から預かっているお金が残っている |
| ゼロ | 貸し借りなし | ちょうど精算できている |
| マイナス | **立て替え中(彼女への貸し)** | 預かりを使い切り、彼女の分をあなたが払っている |

共有ページ(彼女の画面)にも同じ意味が伝わるよう、「あずけているお金ののこり」/「たてかえてもらっている分」と、彼女から見た言い方で出ます。

#### 返金・現金の受け取り・手動調整

「彼女」タブの記録カードで、上の **`預かる / 返す / 調整`** を切り替えて記録します。**どれも履歴に1件の記録として残ります**(あとから「なぜ残高が変わったのか」を必ず追えるようにするためで、残高だけをこっそり書き換える操作はありません)。

- **返す** — 余った預かり金を彼女に返した(残高が減ります)
- **受け取る** — 彼女から現金を受け取った(残高が増えます。「預かり」と同じ扱いです)
- **調整** — 数え間違いなどのズレを直す。増やす/減らすを選び、**理由もいっしょに残ります**

種類を選ぶと、見出し・金額欄のラベル・保存ボタンの文言がそれに合わせて変わります。符号を数字に打ち込ませないよう、調整だけは向き(増やす/減らす)をボタンで選ぶ形にしています。保存の前に「この記録のあと: ◯◯円(預かり中)」と結果が出るので、押す前に確かめられます。

この機能には `supabase/migration-partner-ledger.sql` の実行が必要です(下記)。実行するまでは導線が表示されないだけで、記録・入力・同期はこれまでどおり動きます。

#### 彼女が払った回・2人で分けて払った回

支出の「詳細」に **「支払った人」**(自分が全額 / 彼女が全額 / 分けて払った)があります。既定は「自分が全額」なので、いつもどおりの入力では手数は増えません。

残高への影響は **「彼女が払った額 − 彼女の負担分」** です。

- 自分が全額払った → 彼女の負担分だけ残高が減る(従来どおり)
- 彼女が全額払った → **あなたの負担分だけ残高が増える**(彼女に借りている状態)
- 分けて払った → 彼女が払いすぎた分だけ増え、足りない分だけ減る

こちらも `supabase/migration-partner-ledger.sql` の実行が必要です。

#### 残高が少なくなったときのお知らせ

預かり残高が **1,000円**(既定)を下回ると、入力タブと「彼女」タブに注意が出ます。基準額は「彼女」タブの **「残高が少なくなったら知らせる」** から変えられます(この端末に保存されます)。

Discord 通知を設定していれば、**基準を下回った時点で1回だけ**通知します。下回ったままの日は何日続いても鳴らず、基準以上に戻ると次に下回ったときにまた鳴ります。

### 彼女に見せる共有リンク

彼女は**アプリを入れなくても、アカウントを作らなくても、URL を開くだけ**で状況を確認できます。

1. 「彼女」タブの **「彼女に見せるリンク」** カードで有効期限(7日 / 30日 / 90日 / 期限なし)を選び、**「リンクを発行する」** を押します
2. **「リンクをコピー」** で URL をコピーして、彼女に送ります
3. 彼女がその URL を開くと、次のものだけが表示されます
   - いまの残り(または、立て替えてもらっている額)
   - 自分の分として引かれたもの(日付・お店・カテゴリ・**自分の負担額だけ**)
   - 自分があずけたお金の履歴
   - **返してもらったお金と、直したところ**(日付・金額・理由。`migration-partner-ledger.sql` を実行している場合)
   - **自分が払ったお会計**があれば、そこに「あなたが◯円払いました」と出ます
4. 気になる明細には、彼女がそのページからコメントを書けます。書かれると「彼女」タブに未読の印が出ます(あなたもアプリからコメントを返せます)

> **表示されないもの**(意図的に出していません)
>
> - あなた個人の支出は1件も出ません。出るのは **彼女の負担がある記録** と **彼女自身が払った記録** だけです(どちらでもない記録は、データベースの関数が最初から返しません)
> - 支出の**支払い総額**も出ません。出るのは彼女の負担額と、彼女自身が払った額(彼女がすでに知っている額)だけです
> - 支出・預かりのメモの内容も出ません(返金・調整の理由だけは、残高が動いた理由なので出ます)
> - タグと、分割の内訳の束ね方も出ません

> **注意:** **URL を知っている人は誰でもそのページを開けます**(パスワードはありません)。他の人に知られてしまったら、「彼女」タブの **「リンクを無効にする」**(または「作り直す」)を押してください。押した時点で、閲覧もコメントの書き込みもできなくなります。

コメントには荒らし・誤操作への対策として、1件あたり300文字までの制限と、短時間の連投制限(サーバー側で1分あたり3件・1日あたり50件まで)がかかっています。

明細を削除している間、その明細に付いたコメントは共有ページに出ません(見えない明細のコメントは返さないため)。ただし**コメントそのものは消えていない**ので、削除を取り消して同じ記録が戻れば、コメントも一緒に戻ります。

> 共有リンクを**彼女のスマホで**開くには、[手順 4](#4-リポジトリ-secrets-を設定するの任意) のリポジトリ secrets(`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`)を設定してデプロイしてください。設定していないと、接続情報があなたの端末の中にしか無いため、彼女の端末ではページを開けません(その場合は「彼女」タブに注意書きが出ます)。

### 月末の預かり金サマリー

Discord 通知を設定していると、**月が変わってから最初にアプリを開いたとき**に、前月分のまとめ(使った分の合計・預かった合計・いまの残高・カテゴリ別の内訳)が自動で Discord に送られます。

- サーバー側の定期実行は使わず、繰り返し入力と同じく「アプリを開いたときに、まだ送っていない月ぶんを送る」方式です
- 送信済みの記録は Supabase に残るため、**複数の端末で同じ月が二重に送られることはありません**
- さかのぼるのは直近3ヶ月までです(長く開いていなくても通知が溢れません)
- Discord 通知を設定していないときは何もしません

### 2. Google ログインを設定する

このアプリのログイン方法は **Google アカウントのみ**です。次の手順で Google 認証を有効にします。

1. Supabase の **Authentication → Sign In / Providers → Google** を開き、画面に表示されている **Callback URL**(`https://xxxx.supabase.co/auth/v1/callback` の形)をコピーしておきます
2. [Google Cloud Console](https://console.cloud.google.com/) を開き、Google 側の設定をします
   - 画面上部からプロジェクトを新規作成します(名前は `kakeibo` など何でも構いません)
   - **APIとサービス → OAuth同意画面** を開き、User Type は **External(外部)** を選択します。アプリ名・サポートメール・デベロッパー連絡先を入力して保存します
   - 同じ OAuth同意画面の **テストユーザー** に、自分の Google アカウント(ログインに使うメールアドレス)を追加します(公開申請をしなくても、テストユーザーならログインできます)
   - **APIとサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID** を選び、次のように設定して作成します
     - アプリケーションの種類: **ウェブ アプリケーション**
     - **承認済みの JavaScript 生成元**: `https://<あなたのGitHubユーザー名>.github.io`
     - **承認済みのリダイレクト URI**: 手順 1 でコピーした Callback URL(`https://xxxx.supabase.co/auth/v1/callback`)
3. 作成すると **クライアント ID** と **クライアント シークレット** が表示されます。これを Supabase の **Authentication → Sign In / Providers → Google** の `Client IDs` / `Client Secret` に貼り付け、Google プロバイダを **有効(Enable)** にして **Save** します
4. Supabase の **Authentication → URL Configuration** を開き、
   - **Site URL** に `https://<あなたのGitHubユーザー名>.github.io/kakeibo/`
   - **Redirect URLs** にも `https://<あなたのGitHubユーザー名>.github.io/kakeibo/`

   を設定して保存します(ログイン後にアプリへ戻ってくるために必要です)
5. デプロイが済んだらアプリを開き、**「Googleでログイン」** をタップして自分の Google アカウントでログインします。無事にログインできたら、**Authentication → Settings** の **「Allow new users to sign up」を オフ** にしておきます。こうすると他人が勝手にアカウントを作れなくなるので安心です

> ローカル開発(`http://localhost:5173`)でも Google ログインを試したい場合は、Google Cloud 側の「承認済みの JavaScript 生成元」に `http://localhost:5173`、Supabase の **Redirect URLs** に `http://localhost:5173/kakeibo/` を追加してください。

### 3. GitHub Pages を有効化する

1. このリポジトリを自分のアカウントに用意します(fork またはテンプレートから作成)
2. リポジトリの **Settings → Pages** を開きます
3. **Source** を **GitHub Actions** に変更します

### 4. リポジトリ secrets を設定する(任意)

ビルド時に Supabase の接続情報を埋め込みたい場合は、リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で次の 2 つを登録します。

| Name | Value |
| --- | --- |
| `VITE_SUPABASE_URL` | 手順 1-5 で控えた Project URL |
| `VITE_SUPABASE_ANON_KEY` | 手順 1-5 で控えた anon public キー |

**設定しなくても動きます。** その場合は、デプロイされたアプリに初めてアクセスしたときに表示される設定画面で URL と anon キーを入力してください(ブラウザの localStorage に保存されます)。

なお anon キーは「公開してよい」種類のキーです。データの保護は RLS(本人しか読み書きできないルール)で行われているため、キーが見えても他人はあなたのデータにアクセスできません。

main ブランチに push(またはマージ)すると、GitHub Actions が自動でビルドして GitHub Pages に公開します。手動で実行したい場合は **Actions → Deploy to GitHub Pages → Run workflow** からも実行できます。

(リポジトリ名を `kakeibo` 以外にした場合は、`vite.config.ts` の `base` をそのリポジトリ名に合わせて変更してください)

2. 画面下の共有ボタン(四角から上矢印)をタップします
3. 「ホーム画面に追加」を選び、「追加」をタップします

**Android (Chrome)**

2. 右上のメニュー(︙)をタップします

## Discord通知の設定

彼女の預かり残高が増減したとき(預かりの記録・彼女負担分つきの支出・記録の修正/削除)に、Discord のチャンネルへ自動で通知を送れます。彼女がそのチャンネルの通知を受け取るようにしておけば、残高の動きを2人でリアルタイムに共有できます。

1. [Discord](https://discord.com/) で2人用のサーバーを作成し、彼女を招待します(既存のサーバーがあればそれでも構いません)
2. 通知用のチャンネル(例: `#家計簿`)を作成し、チャンネル設定(⚙️)→ **連携サービス** → **ウェブフック** → **新しいウェブフック** をクリックして、**ウェブフックURLをコピー** します
3. アプリの「彼女」タブにある **Discord通知** カードに、コピーした URL を貼り付けて **保存** します。続けて **テスト送信** を押し、チャンネルに「✅ 家計簿アプリと接続できました」と届けば設定完了です
4. 彼女側は、そのチャンネルの通知を ON にします(モバイルの Discord アプリでチャンネルを長押し → **通知設定** → プッシュ通知を「すべてのメッセージ」に。サーバー全体をミュートしていると届かないので注意してください)

**設定は端末をまたいで共有されます。** Webhook URL は Supabase の `discord_settings` テーブル(あなた専用の1行)に保存され、localStorage はその控えとして使われます。スマホで設定すれば PC にも、PC で設定すればスマホにも反映され、**「解除」も同じように全部の端末へ伝わります**。以前は設定した端末の中だけに保存されていたため、**設定していない端末(たとえばスマホ)から記録した分は通知されない**という抜けがありました。

> **注意:**
>
> - 同期には [`supabase/migration-discord-webhook.sql`](supabase/migration-discord-webhook.sql) の実行が必要です。未実行のときは従来どおり端末の中だけに保存され、**通知は届きますが、設定した端末で記録した分だけ**になります(その旨が Discord通知カードに表示されます)。すでに設定してある端末でアプリを開けば、その URL は自動でサーバーへ引き上げられるので、貼り直す必要はありません
> - 設定が食い違ったときは **サーバー側の値が優先** されます(どこかの端末で押した「保存」「解除」が、別の端末の古い控えで巻き戻らないようにするためです)
> - Webhook URL を知っている人は誰でもそのチャンネルにメッセージを書き込めてしまいます。**URL は第三者に共有しないでください**。画面には先頭40文字までしか表示されないので、**秘密のトークン部分は表示されません**
> - 端末を貸す・売るときは、ログアウト時の確認で端末内のデータを消してください。Webhook URL はサーバーに残るので、**次にログインすれば設定し直さずに戻ります**(Gemini の APIキーは同期していないので、こちらは入れ直しになります)

### これまでの履歴をまとめて送る(過去ぶんの追いつき)

Webhook URL が端末ごとだった頃は、**設定していない端末(たとえばスマホ)から記録した分が通知されていません**。つまり彼女は、その間の増減をほとんど知らないままです。これを後から追いつかせるために、「彼女」タブの **Discord通知** カード(設定済みのときだけ出ます)から **「これまでの履歴をまとめて送る」** を開けます。

**送るのは彼女に関係する記録だけです。** 共有リンクの画面とまったく同じ範囲で、**あなた個人の支出は1件も含みません**(支払い総額も出ません)。

- 預かり・返金・調整
- 彼女の負担分がある支出、彼女が払った回

送られる文面は、**期間と件数・はじめの残高 → 明細(日付・内容・影響額・その時点の残高)→ いまの残高** の順です。

```
📖 これまでの預かり金の記録(1/2)
期間: 2026年5月1日(金) 〜 2026年7月28日(火)・62件
はじめの残高: ¥0(貸し借りなし)
「残り」はあずかっているお金、「立て替え」は使い切って私が払っている分です
────────
5月1日(金) 彼女から預かり +¥30,000 → 残り ¥30,000
6月1日(月) 一緒の夕飯 −¥500 → 残り ¥29,500
7月20日(月) 居酒屋 +¥1,200 → 残り ¥3,842(彼女が ¥2,000 払い、負担 ¥800)
   ……
────────
いまの残高: ¥570(立て替え中(彼女への貸し))
```

**押す前に、何件が何通で届くのかと、1通目の実物が出ます。** 押した瞬間に彼女の通知欄がいくつ埋まるのかを、知らないまま押させないためです。

- **期間を選べます** — 前回の続き(既定)/ 全期間(送り直す)/ 年 / 月
- **同じものが二度届きません** — どこまで送ったかを Supabase(`partner_backlog_sends`)に覚えるので、次は続きだけが送られます。**別の端末で開いても同じ**です(この機能が必要になった原因が「設定が端末の中にしか無かったこと」なので、送信の記録も端末に閉じ込めていません)
- **もう一度送りたいときは**「全期間(送り直す)」や年・月を選べば、送信済みでも構わず送れます
- **1件1通にはしません** — Discord の上限(1通2,000文字)に収まるところまで詰めて送るので、100件でもおよそ2〜4通です
- **1通ずつ間隔を空けて送ります**(1.2秒。Discord の Webhook は2秒に5回を超えると断られます)。送信中は「送信中… 3/10通」と出ます
- **途中で失敗しても壊れません** — 10通のうち3通目で失敗したら、2通目までを送信済みとして残し、失敗の理由(原因ごとの対処つき)を出します。もう一度「前回の続き」を送れば、**届いていない分だけ**が送られます
- **画面の金額を伏字にしていても、送る中身は伏せません**(彼女が読む文章のため)

> この機能には [`supabase/migration-partner-backlog.sql`](supabase/migration-partner-backlog.sql) の実行が必要です(下記)。実行しなくても送信そのものは動きますが、**どこまで送ったかがその端末の中だけに残る**ため、別の端末から開くと「前回の続き」が分かりません(その旨が画面に表示されます)。

### 旅行1回ぶんのまとめを彼女に送る

旅行のあいだは残高の通知が細切れに何十通も流れるので、**帰ってから1回ぶんをまとめて**渡せる導線があります。レポートの「タグ別の支出」で旅行を選び、「回ごと」の行の **「この回を彼女に送る」** を押します(Discord を設定しているときだけ出ます)。

**送るのは彼女に関係する記録だけです。** 共有ページ・そのつどの通知・履歴のまとめ送信と**まったく同じ条件**(彼女の負担がある支出、または彼女が払った回)で、**あなた個人の支出は1件も含みません**。除いた件数は画面に出ます。

```
🧳 #2026和歌山 のまとめ
期間: 2026年8月6日(木) 〜 2026年8月8日(土)(3日間)
タグ: #旅行 #2026和歌山
あなたに関係する記録: 18件
あなたの負担の合計: ¥12,060
私だけの支出(あなたの負担が0のもの)は入っていません
────────
8月6日(木) 旅館 ¥8,000
8月7日(金) 昼ごはん ¥1,500(あなたが ¥3,000 払いました)
   ……
────────
カテゴリ内訳(あなたの負担)
食費 ¥8,160(12件)
宿泊 ¥3,900(6件)
────────
この旅行で、あずかっているお金から ¥12,060 を使いました
いまの残高: ¥13,940(預かり中)
```

- **押す前に、何通で届くのかと1通目の実物(文字数つき)が出ます**
- **分割・間隔・途中失敗からの再開は、履歴のまとめ送信とまったく同じ仕組み**です(1通2,000文字・1.2秒間隔)。途中で失敗したら **「残りの◯通を送る」** でそこから続けられます(届いた分は二度送りません)
- 残高の数字は、画面と同じ計算(`partnerBalance`)を通しています
- **同じ旅行を二度送ることもできます。** 金額を直した・付け忘れを足した・彼女が通知を消した、といった場面があるので**止めません**。そのかわり2回目からは、画面に「◯月◯日に送信済みです」と出て、届くメッセージの見出しにも **「(送り直し)」** が付きます(彼女が2回ぶんの支出と読み違えないため)。この控えは端末の中だけに持ちます(覚え書きなので、マイグレーションは要りません)
- **画面の金額を伏字にしていても、送る中身は伏せません**(彼女が読む文章のため)

## レシート読み取りの設定

入力タブの **「📷 レシートを読み取る」** ボタンで、レシートをカメラで撮影するだけで店名・合計金額・日付をフォームに自動入力できます。読み取りには Google の無料 AI「Gemini」を使うため、最初に一度だけ無料の API キーを設定します(クレジットカード登録は不要です)。

1. [Google AI Studio](https://aistudio.google.com/apikey) をスマホまたは PC のブラウザで開きます
2. 自分の Google アカウントでログインします
3. **「Create API key」**(APIキーを作成)をタップし、表示されたキーを **コピー** します。現在発行されるキーは `AQ.` で始まります(以前に発行した `AIza` で始まる古い形式のキーもそのまま使えます)
4. アプリの入力タブで **「📷 レシートを読み取る」** をタップすると設定シートが開くので、コピーしたキーを貼り付けて **保存** します
5. もう一度 **「📷 レシートを読み取る」** をタップするとカメラが起動します。レシート全体が写るように撮影すると、数秒で店名・合計金額・日付がフォームに入力されます(カテゴリは、そのお店を以前に記録していれば自動で入ります)

### 溜めたレシートを続けて撮影する

入力タブの **「レシートを続けて撮影する(最大5枚)」** をタップすると、複数枚をまとめて処理できます。

1. 「撮影する」で1枚撮ると、その場で読み取りが始まります。読み取り中でも「続けて撮影」で次の1枚を追加できます(最大5枚)
2. 無料枠とレート制限に配慮して、**1枚ずつ順番に**読み取ります
3. 各枚の金額・お店・日付・カテゴリはその場で修正でき、いらない枚は「破棄」できます
4. 1枚が失敗しても他の枚は止まりません。失敗した枚には理由が表示され、「再試行する」で撮り直さずにやり直せます
5. 最後に **「◯件をまとめて記録する」** を押すと、確認した枚だけが一度に記録されます

### 使用するAIモデルについて

アプリはモデル名を決め打ちせず、**その時点で利用可能なモデルを一覧から自動選択**します(無料枠の対象である Flash 系を優先します)。選ばれたモデル名は設定シートに表示され、端末内にキャッシュされます。

Google が古いモデルの提供を終了しても、アプリが自動でモデルを選び直すため、通常は何もする必要はありません。もし読み取りがモデル関連のエラーで失敗し続ける場合は、設定シートの **「接続テスト」** を押してください。その場でモデルを選び直します。

> **注意:**
>
> - Gemini の無料枠は 1 日あたり約 1,500 回のリクエストまで使えます。家計簿のレシート読み取りには十分すぎる量なので、通常の使い方で料金が発生することはありません
> - API キーは設定した端末(ブラウザ)の localStorage にのみ保存されます。別の端末で使う場合は、その端末でもキーを設定してください
> - 読み取り時、撮影したレシート画像は Google の API に送信されます。気になる場合は使用を控えてください
> - AI の読み取りは完璧ではありません。**読み取り結果(特に金額)を必ず確認し、必要なら修正してから保存**してください

## データの保存場所とセキュリティ

記録したデータはすべて自分の Supabase プロジェクト(無料枠)の PostgreSQL に保存されます。`transactions` のほか、`categories`(カテゴリ設定)・`store_categories`(お店ごとのカテゴリの記憶)・`recurring_rules`(繰り返し入力)・`transaction_templates`(テンプレート)・`partner_share_links`(共有リンク)・`partner_share_comments`(明細へのコメント)・`partner_summary_sends`(月末サマリーの送信記録)・`partner_backlog_sends`(履歴のまとめ送信でどこまで送ったか)・`transaction_changes`(変更履歴)・`assets`(資産・負債の定義)・`asset_balances`(残高のスナップショット)・`discord_settings`(Discord 通知の送り先)を使います。いずれのテーブルにも Row Level Security (RLS) が設定されており、**ログインした本人の行しか読み書きできません**。anon キーが公開されていても、他人があなたのデータを参照・変更することはできない仕組みです。

`discord_settings` に入る Webhook URL は「知っていれば誰でもそのチャンネルに投稿できる」トークンです。RLS で本人の行に限ったうえで、共有ページが使う anon ロールからは**テーブル権限そのものを剥がしています**(`revoke all on table public.discord_settings from anon;`)。端末の localStorage に置いていた頃と比べて危険は増えず、むしろ端末を失くしたときはログアウトの後始末で端末側だけを消せます。レシート読み取りに使う Gemini の APIキーは、**同期していません**(撮るのはスマホだけで持ち歩く必要がなく、鍵は動かさない方が安全なため)。

### 共有リンクのしくみ(彼女はログインしないのに、なぜ安全か)

彼女はアカウントを持たないため、共有ページは公開されている anon キーでアクセスします。そこで次の二段構えにしています。

1. **anon にはテーブルの権限を渡していません。** `migration-partner-share.sql` が `transactions` などから anon の権限を明示的に剥がしており(`revoke all on table public.transactions from anon;`)、共有ページから明細テーブルを直接読むことはできません。
2. **彼女に見せる行は、データベース側の関数(`partner_share_view`)が組み立てて返します。** この関数はリンクのトークンを受け取り、有効なリンクのときだけ「預かり残高」「預かった履歴」「彼女の負担分がある支出(負担額のみ)」を返します。彼女の負担が 0 円の支出も、支払い総額も、返り値に含まれません。トークンが無効・期限切れ・無効化済みのときは、理由を区別せず同じ「開けません」を返します(存在の有無を漏らさないため)。

コメントの書き込みも同じで、`partner_share_add_comment` という関数だけを通します(anon の直接 INSERT はできません)。この関数の中で、文字数(300文字)と連投(1分3件・1日50件)をサーバー側で制限し、リンクが無効化されていれば書き込みも止まります。

トークンは `gen_random_bytes` による48文字のランダムな文字列で、共有 URL の **`#` より後ろ**に置いています。`#` 以降はブラウザからサーバーへ送られないため、トークンがアクセスログや外部サイトへの Referer に残りません。
