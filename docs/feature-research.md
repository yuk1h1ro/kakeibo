# 家計簿アプリ 機能調査レポート

## この調査について

この家計簿アプリ（kakeibo）に次に何を実装するかを決めるための、事前調査の記録です。目的は「既存の家計簿アプリにどんな機能があるかを網羅的に把握し、そのうえで必要なものだけを実装する」ことにあります。思いついた順に作るのではなく、選択肢の全体像を先に並べてから選ぶ、という進め方をとりました。

- **調査日**: 2026-08-04
- **調査方法**: 機能領域を5つに分け（(1) 入力・記録 / (2) 分析・レポート・予算 / (3) 共有・精算・連携・通知 / (4) UX・使い勝手の細部 / (5) ニッチ・変わり種）、それぞれ独立に国内外のアプリを調べたうえで、5本の結果を突き合わせて重複を排除し、**251機能**の一覧に統合しました。各機能には「採用しているアプリ」「実装コストの目安（小/中/大）」を付け、本アプリで実装済みのもの、および調査を通じておすすめと判断したものに印を付けています。
- **実装コストの目安**: **小** = 数時間〜数日（既存データの集計・表示や UI のみ） / **中** = 数日〜2週間（新しいデータモデルや状態管理が必要） / **大** = 2週間以上（外部連携・推論・大幅な UX 追加が必要）

# 重点まとめ

分野別の一覧とは別に、各調査レポートで「特に効く」と評価されていたものを抜き出します。番号は本編の通し番号です。

## 使いすぎ抑制に効果が高いと評価されている機能（トップ5）

分析・レポート・予算の分野の調査で、公式資料やレビュー記事の評価をもとに順位づけされたものです。

1. **単一の「今使っていい額」表示**（→ 025「今日あといくら使えるか」/ 217「固定費を引いた『本当に自由な残額』」）
   PocketGuard のレビュー群が一貫して「お金の全体像を1つの数字に還元する」点を最大の価値としており、The Penny Hoarder は同アプリを「A Budgeting App Built Around One Number」と題しています。複数の数字を見比べる認知コストがゼロになるため、レジの前で判断できるのが強みです。
2. **ゼロベース予算＋予算の付け替え（YNAB 方式）**（→ 031「ゼロベース予算」/ 032「余った予算の付け替え」）
   YNAB 公式統計では新規ユーザーが最初の2ヶ月で平均 $600、初年度で $6,000 以上を節約すると公表されています。レビュー記事は「使った額を後から見る他アプリと違い、いま手元にある現金を先に割り当てさせる」点が行動変容の源だと分析する一方、週数回のチェックインという継続コストが前提だとも指摘しています。
3. **袋分け／プリペイド前払い（B/43 のポケット・チャージ方式）**（→ 030「袋分け（封筒）方式」）
   スマートバンクの発表と各種レビューは「毎月の予算をプリカにチャージし、それ以上使えない」構造そのものが使いすぎ防止だと説明しています。袋分け家計簿系アプリのレビューでも「その月に使える額と残高が見える化されることでコントロールしやすくなる」と共通して評価されており、物理的に上限があるため意志の力に依存しないのが理由です。
4. **サブスク／定期支払いの自動検出と値上がり通知**（→ 122「サブスク合計の可視化」/ 081「定期支出の自動検出と登録提案」/ 246「使っていないサブスクを名指しで煽る通知」）
   Rocket Money は複数のレビューで「隠れた定期費用を見つけるアプリとしては市場最良」と評価され、Emma も「money leaks（お金の漏れ）を止める」を前面に出しています。1回の見直しで毎月効果が続く、つまり努力量あたりの削減額が最大というのが評価理由です。
5. **段階的な予算超過アラートと週次サマリー通知**（→ 028「予算 80% / 100% の段階アラート」/ 135「週次サマリー通知」）
   Moneytree は予算の80%到達時と100%到達時の2段階通知を提供しています。Emma のレビューは「週次レポートが、外食に想定より使っていることを小さな単位で気づかせる」と評価。B/43 はさらにペアの相手にも同時通知されます。使い切ってからではなく手前で介入する点、および他者の目が入る点が効くと分析されています。

## 20代男性の使いすぎ抑制に効きそうなニッチ機能（8選）

ニッチ・変わり種の分野の調査から、狙いを絞って選ばれた8つです。

1. **Left to spend（固定費控除後の自由残額を1つの数字で出す）**（→ 217）
   費目別の細かい予算管理は続きにくい一方、「今月あと使っていいのは◯円」という単一の数字なら意思決定コストがほぼゼロで、判断のたびに参照できます。日割りに割るとさらに効きます。
2. **Pre-Qubing（会計前に自分で金額を入力する）**（→ 218「レジで会計前に自分で金額を打つ」）
   使いすぎの本質は「使った瞬間に痛みがない」ことにあります。レジで自分の指で金額を打ち込む一手間が、キャッシュレスで失われた痛覚を復活させます。カード決済をブロックする方式ほど過激でないので離脱しにくいのが利点です。
3. **Guilty Pleasure Rule（悪癖に使ったら罰金貯金）**（→ 220「悪癖に使ったら罰金貯金」）
   コンビニ・ソシャゲ課金・深夜の出前など自覚のある悪癖に「使ったら +300円 貯金」を課します。罰であると同時に貯金なので嫌悪感が薄く、しかも支出単価が実質1.3倍になるため抑止が効きます。
4. **Spend Less Rule（特定店の上限＋差額を貯金）**（→ 221「特定の店の上限＋下回った差額を貯金」）
   「コンビニは週2,000円まで、下回ったら差額を貯金」。禁止ではなく「勝ったら報酬」のゲーム設計なので、我慢が損に感じられません。抑制系の機能では最も継続率が高いタイプと評価されています。
5. **サブスク自動検出＋未使用アラート**（→ 122 / 081 / 246）
   動画・音楽・ゲーム・ジムなど月額の重複を抱えがちで、しかも「解約が面倒」で放置されます。自動検出は本人の努力ゼロで数千円/月の削減が出る、最も費用対効果の高い機能とされています。値上がり通知とセットにするとさらに効きます。
6. **感情スタンプ（後悔フラグ）と「後悔率」の月次サマリ**（→ 219「感情スタンプ（満足 / 普通 / 後悔）」）
   金額だけ見ても行動は変わりませんが、「今月の後悔支出は12件・18,400円」「後悔が多いのは金曜23時以降」という形で出されると刺さります。実装コストは極小（1タップの3値）なのに、洞察の質が跳ね上がります。
7. **上書き合計（月初からの累計を常に突きつける）**（→ 216「上書き合計（毎行に月初からの累計）」）
   づんの家計簿の中核アイデアです。1回3,000円は安く見えますが「今月ここまで87,000円」と累計で見せると心理的な効き方がまったく違います。実装は極小で、既存の記録画面に列を1つ足すだけです。
8. **Salary Sorter＋袋分け（給料日に自動で分ける）**（→ 223「給料日に自動で袋へ振り分ける」/ 030）
   意志力を月に1回、しかも給料日だけに集中させる設計です。残った額しか手元に見えないので、その後の1ヶ月は何も考えなくて済みます。「見える残高そのものが減る」実装だとさらに強くなります。

なお、**おつり貯金**と **Roast Mode 的な煽り通知**も候補に挙がりましたが、前者は抑制よりも貯金体験の入口として、後者は好みが割れる（刺さる人には非常に刺さるがアンインストールの引き金にもなる）ため、次点とされています。

## 「彼氏が立て替え → 彼女から預かった金から差し引く」に効く機能（12選）

共有・精算の分野の調査から、このアプリの中核ユースケースに直結する順に並べられたものです。

1. **預かり金残高の台帳化（前受金モデル）**（→ 001、実装済み）
   「預かり」と「取り崩し」を両方トランザクションとして持ち、残高は集計で導きます。近い発想として Zeta の Bill Reserve、かぞくのおさいふの家族残高があります。
2. **支出入力時の「相手負担分」欄と即時差引**（→ 002、実装済み）
   実装済みですが、按分 UI の強化余地が大きいと評価されています。
3. **按分クイック指定（全額/半額/割合/実額）**（→ 003 実装済み / 006「割合（%）指定の按分」/ 007「『÷2』『÷3』の割り勘ボタン」）
   Splitwise・Settle Up の split type UI が参考になります。手入力の摩擦が最大の離脱要因とされています。
4. **端数処理と丸め単位の設定**（→ 008「端数の丸め設定（10円/100円単位）」）
   3,333円を1,700/1,600 に丸め、端数は立て替えた側が吸収します。恋人間では「多めに持つ側」を固定できると角が立ちません。
5. **残高低下アラート／残高不足の扱い**（→ 010「預かり残高の低下アラート」/ 011「残高マイナス（＝彼女への貸し）の扱い」）
   Zeta の daily balance alerts、マネーフォワード ME の残高不足通知が該当例です。
6. **預かり金の入金・返金・調整の記録**（→ 012「預かり金の『返金』『手動調整』」）
   追加で預かる、余りを返す、手動で残高を合わせる、の3操作です。監査可能性のために「調整」も履歴に残すのがポイントで、Splitwise の balance adjustment が参考になります。
7. **自分の実質支出での集計**（→ 004、実装済み）
   相手負担分を除いた「自分が本当に使った額」を出します。実装済みで、これが Splitwise 系の競合にはない差別化点だと評価されています。
8. **明細つき残高の読み取り専用共有リンク**（→ 179「閲覧専用の共有リンク」）
   彼女がアプリを入れず URL だけで「何にいくら使われて残りいくらか」を確認できます。Settle Up の group link、Tricount の共有リンクが該当。信頼の担保として効果が大きく、コスパが最も良いとされています。
9. **取引ごとのコメントと絵文字リアクション**（→ 185「明細へのコメント」/ 186「絵文字リアクション」）
   「これ何？」を明細上で解決します。Honeydue のコメント＋絵文字が最もこのユースケースに近い設計です。
10. **レシート添付（既存 OCR の副産物を保存）**（→ 063「レシート画像を明細に添付して保存」）
    OCR は既にあるので、画像保存を足すだけで済みます。
11. **月次の預かり金サマリー通知**（→ 016「月末に預かり金サマリーを Discord へ」）
    月末に「今月の取り崩し合計・残高・内訳」を両者に届けます。Splitwise の monthly summary が実質のリマインダーとして機能している例です。
12. **締めて清算（月次クローズ）**（→ 013「月次クローズ（締めて清算）」）
    締め日で残高を確定し、精算か繰り越しかを選びます。以後その月は編集ロック。日本の同棲家計運用の定番で、「言った言わない」を構造的に防げます。

補足として、Splitwise 系（貸し借りをネット残高で持つ）と本アプリ（先に預かってデポジットを取り崩す）は数学的にはほぼ同型で、違いは残高の符号と初期値だけである、という観察が記録されています。したがって「預かり金」を汎用の双方向の貸借残高に一般化しておくと、彼女が立て替えた場合も同じテーブルで扱え、後の拡張が安くなります。

## 「これが無いと使い続けられない」と評価されがちな基本機能（10項目）

UX の分野の調査が、レビュー記事の減点理由から逆算して挙げた10項目です。

1. **3タップ以内で1件記録できる手動入力導線**（→ 046「起動直後が入力画面」実装済み / 051「カテゴリを先に選んで金額を打つ2タップ入力」）
   おカネレコ「2秒」、MoneyNote「起動するとすぐ入力画面」がそれぞれ最大の訴求点になっています。自動連携アプリでも現金の手入力導線が貧弱だと続きません。
2. **カテゴリの自由な追加・編集・並べ替え・非表示**（→ 082 実装済み / 085「カテゴリのドラッグ並べ替え」/ 086「カテゴリの非表示（削除せず隠す）」）
   既定カテゴリが自分の生活に合わないことは必ず起きます。数の上限と、過去データを壊さずに整理できることの両方が要ります。
3. **月次の集計と、月をまたぐ移動＋当月へ戻る**（→ 124 実装済み / 126「『当月へ戻る』ボタン」）
   「今月いくら使ったか」は最小単位の価値です。月移動が重い・戻れないアプリは使われなくなります。
4. **カテゴリ別の内訳グラフ＋そこからの明細ドリルダウン**（→ 105 実装済み / 108「グラフをタップして明細へドリルダウン」）
   見るだけのグラフではなく、必ず明細に降りられることが条件です。
5. **フリーワード検索と期間・カテゴリ絞り込み**（→ 145「フリーワード検索（店名・メモ）」/ 116「複数条件の絞り込み検索＋その場で合計」）
   記録が数百件を超えた瞬間に必須化します。OsidOri は「検索が無いので見返しに手間」と明確に減点されています。
6. **編集・削除と、取り消せる安心感**（→ 156 実装済み / 159「削除直後の『元に戻す』」/ 204「削除した記録の復元（ゴミ箱）」）
   打ち間違いは日常です。削除の Undo（またはゴミ箱）がないと入力が慎重になり、慎重さが継続を殺します。
7. **予算設定と残額のリアルタイム表示**（→ 022「カテゴリ別の月次予算」/ 023「全体予算だけの簡易モード」/ 024「予算バー＋信号色」）
   「あといくら使えるか」が家計簿を記録から意思決定に変えます。カテゴリ別予算と全体予算の両方が要ります。
8. **データのバックアップ・復元と機種変更時の移行**（→ 198「CSV エクスポート」/ 201 実装済み）
   「機種変でデータが消えた」は復帰不能な離脱理由です。エクスポート（CSV）まであると信頼が段違いになります。
9. **パスコード／生体認証ロック**（→ 207「パスコード / Face ID ロック」）
   金額が人に見られる不安を消します。人前で開けないアプリは開く機会自体が減ります。
10. **オフラインでも記録できること／即座に保存されること**（→ 157 実装済み / 158 実装済み）
    電波の悪いレジ前・地下・機内で記録できないと、その1件は永遠に記録されません。自動保存と楽観的 UI もここに含まれます。

調査中に繰り返し出てきた共通見解は「続かない理由の大部分は記録のタイミングと入力の手間にあり、入力の摩擦を下げることが継続への一番の近道」「完璧に管理しようとするほど続かなくなる」の2点でした。機能を足すよりタップ数を1つ減らす方が効く局面が多い、というのがこの調査全体の結論です。

# 調査対象外としたもの

網羅調査では見つかったものの、このアプリでは実現できない・割に合わないと判断して、機能カタログに含めなかったものです。

| 対象外にしたもの | 理由 |
|---|---|
| 銀行・クレジットカード・電子マネーの自動連携（自動記帳） | 日本ではアグリゲーター事業者との有料契約が事実上必須で、個人開発の無料アプリでは手が届きません。 |
| プリペイドカード・デビットカードの自社発行（決済＝即記録） | 金融ライセンスと決済事業者としての体制が必要で、アプリ開発の範囲を超えます。 |
| レシート入力の人力代行（Dr.Wallet 方式） | オペレーターの人件費が継続的にかかり、無料の個人利用アプリでは成立しません。 |
| iOS ネイティブ機能（ホーム画面ウィジェット・Apple Watch・Siri ショートカット・ロック画面からの1タップ入力） | 本アプリは PWA のため、iOS ではこれらの API を利用できません。 |
